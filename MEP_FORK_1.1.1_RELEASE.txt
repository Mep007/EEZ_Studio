Changes since MEP Fork 1.1.0
----------------------------
Native LVGL projects with EEZ Flow disabled can now pass read-only boolean
UserWidget properties into generated create/tick functions. Values can be
true/false literals, native global boolean variables, or boolean properties
of an enclosing reusable widget. Local boolean reads support unary negation.
Unsupported input expressions cause an explicit export error.

Example: Button_quick defines show_toggle and show_mute. Its internal images
use !show_toggle and !show_mute for the Hidden flag. Each instance can use its
own literal or live native boolean binding. Repeated instances keep their own
reserved object-pointer spans; theme, tick and application accessors stay valid.

This is read-only boolean input support, not a general native expression engine.
String, integer and assignable UserWidget properties are unchanged. Flow-based
projects keep their existing property/parameter handling. Generated App/UI bridge
API version remains unchanged. Existing 1.1.0 nested-object and lifecycle fixes
are retained; upstream dependencies have not been broadly upgraded.

builder configuration can be rebuilt using the individual package.json scripts.
Do not run clean-dist when retaining earlier release artifacts.

Windows installer command:

    $env:CSC_IDENTITY_AUTO_DISCOVERY = 'false'
    $env:CI = 'false'
    .\node_modules\.bin\electron-builder.cmd --win nsis --x64 --config electron-builder.yml --config.win.signAndEditExecutable=false --config.directories.output=dist/mep-fork-v1.1.1 --config.artifactName="EEZ Studio MEP FORK v1.1.1 Setup.exe" --publish never
