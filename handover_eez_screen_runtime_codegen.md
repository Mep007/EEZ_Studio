# EEZ Studio MEP Fork - Screen Runtime Codegen Handover

Date: 2026-07-15
Branch: `mesp-lvgl-codegen`
Release: `MEP FORK v1.0.2`
Status: validated and prepared for commit

## Goal

Make LVGL screen handling safe for hierarchical `objects` structs and provide a
small generated runtime API that can be shared by STM32 and ESP32 projects.

The old generated code treated `objects_t` as a flat pointer array:

```c
((lv_obj_t **)&objects)[index]
```

That is not valid once screens and widgets are stored in nested structs. It is
especially unsafe with multiple screens because a screen root is no longer
guaranteed to be the next pointer in the flattened memory layout.

## Main Implementation

The implementation is in:

```text
packages/project-editor/lvgl/build.ts
```

The generator now emits an explicit descriptor table for every non-user-widget
screen. Each descriptor contains:

```c
enum ScreensEnum id;
lv_obj_t **root;
void (*create)(void);
void (*tick)(void);
```

Generated code no longer discovers screen roots by casting `objects_t` or by
using `screen_id - 1` as an object index.

## Generated Screen API

The generated `screens.h` contains:

```c
SCREEN_ID_NONE
SCREEN_ID_COUNT
UI_SCREEN_COUNT

bool ui_screen_is_valid(enum ScreensEnum screen_id);
lv_obj_t *ui_screen_get_root(enum ScreensEnum screen_id);

enum ScreensEnum ui_screen_get_requested(void);
enum ScreensEnum ui_screen_get_loading(void);
enum ScreensEnum ui_screen_get_active(void);

bool ui_load_screen_anim(
    enum ScreensEnum screen_id,
    lv_screen_load_anim_t animation,
    uint32_t duration,
    uint32_t delay
);

bool ui_load_screen(enum ScreensEnum screen_id);
void loadScreen(enum ScreensEnum screen_id);
void loadScreenAnim(
    enum ScreensEnum screen_id,
    lv_screen_load_anim_t animation,
    uint32_t duration,
    uint32_t delay
);

bool ui_is_initialized(void);
void ui_screens_init(void);
void ui_screens_tick(void);
```

For LVGL 8 the generator uses `lv_scr_load_anim_t`, `lv_scr_load_anim()` and
the `LV_SCR_LOAD_ANIM_*` constants. LVGL 9 output uses the corresponding
`lv_screen_*` API.

`ui_load_screen()` is the default wrapper:

```c
return ui_load_screen_anim(
    screen_id,
    LV_SCREEN_LOAD_ANIM_FADE_IN,
    200U,
    0U
);
```

The final `auto_delete` argument is intentionally fixed to `false`. Generated
screens are created statically during initialization and `objects` keeps their
pointers. Automatic deletion would invalidate those pointers. It should only be
revisited together with lazy screen creation and deletion support.

The camel-case `loadScreen()` and `loadScreenAnim()` functions are compatibility
wrappers for older project code. A custom project template that still defines
its own `loadScreen()` must remove that definition during migration to avoid a
duplicate symbol.

## Lifecycle And Tick API

Generated screen roots receive LVGL event handlers. User code can register:

```c
void ui_set_screen_event_callback(
    ui_screen_event_cb_t callback,
    void *user_data
);

void ui_set_screen_tick_callback(
    ui_screen_tick_cb_t callback,
    void *user_data
);
```

Lifecycle events are:

```text
UI_SCREEN_EVENT_LOAD_START
UI_SCREEN_EVENT_LOADED
UI_SCREEN_EVENT_UNLOAD_START
UI_SCREEN_EVENT_UNLOADED
```

Requested, loading and active screen IDs are tracked separately. Loading an
already active root is handled explicitly because LVGL does not emit a normal
load sequence for the same active screen.

`ui_screens_tick()` calls the generated tick function for the active screen and
then the optional user tick callback. The user callback is only called when the
active ID resolves to a valid descriptor, so it never receives
`SCREEN_ID_NONE`.

## Screen Create/Delete/Tick

Generated by-ID create, delete and tick helpers use the descriptor table. The
previous `screen_id - 1` indexing has been removed from these paths.

`ui_screens_init()` is idempotent. It creates the screens, attaches lifecycle
event handlers and marks the generated runtime initialized.

The generated `LVGL_LOAD_FIRST_SCREEN` fragment now calls:

```c
ui_load_screen(SCREEN_ID_<FIRST_SCREEN>);
```

## Generated Theme API

For LVGL projects without EEZ Flow support, the generator also emits:

```c
UI_THEME_COUNT
UI_COLOR_COUNT

bool ui_theme_set(enum Themes theme);
enum Themes ui_theme_get(void);
lv_color_t ui_theme_get_color(enum Colors color);
```

The selected theme can be set before screen initialization and is applied when
the screens are created. Existing `change_color_theme(uint32_t)` remains as a
compatibility wrapper.

## Required Project Template Migration

Projects with a custom generated `ui.c` template must remove:

```text
currentScreen
getLvglObjectFromIndex()
((lv_obj_t **)&objects)[index]
screen_id - 1 screen mapping
their own loadScreen() implementation
direct tick_screen(currentScreen)
```

The non-Flow template should use:

```c
void ui_init(void) {
    ui_screens_init();
    ui_load_screen(SCREEN_ID_<FIRST_SCREEN>);
}

void ui_tick(void) {
    ui_screens_tick();
}
```

Projects should not be regenerated with this fork until their custom templates
and private helpers have been checked for symbol collisions.
