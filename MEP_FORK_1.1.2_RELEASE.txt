Fix
---
Generated text, binary resources and the build manifest now use a temporary
file in the destination directory followed by atomic replacement. Existing
outputs are not opened with truncation. This fixes the locally reproduced
UNKNOWN/open screens.h export failure. Unchanged files retain their timestamps.
If replacement fails, the previous output is retained and the temporary file
is removed. Non-regular output targets are rejected rather than followed.

This is generated-output protection, not whole-export transactionality.
An error can still leave a mixture of successfully generated and older files;
do not compile an export reporting errors. No generated UI files need deleting
and no broad permission or security-setting changes are required.

Validation
----------
Run npm run test:mep in a C compiler environment and npm run build-src.
The regression suite includes generated C bridge lifecycle, nested widgets,
atomic text/binary replacement, unchanged-output timestamps and injected
replacement failure retaining the original output.

Windows packaging
-----------------
Keep prior dist releases. Use electron-builder --win nsis --x64 with the existing
electron-builder.yml, win.signAndEditExecutable=false, publish never, output
dist/mep-fork-v1.1.2 and artifactName EEZ Studio MEP FORK v1.1.2 Setup.exe.
The installer remains unsigned. Verify packaged and installed MEP identity and
export the saved user project before reporting installation complete.
